# TouchGrass backend

## Configure and run

1. Set `MONGODB_URI` to a reachable MongoDB connection string. Startup uses it
   for the existing database health check.
2. Install and run Ollama locally, and set `OLLAMA_MODEL` to a model available
   in your Ollama installation. Set `OLLAMA_BASE_URL` if Ollama is not at
   `http://localhost:11434`.
3. From this directory, run `npm install` if dependencies are not installed, then
   run `npm run dev` for development or `npm start` to start the server.

The API listens on port `5001` by default. Set `PORT` in `.env` to change it.
Startup waits for MongoDB to connect and exits with an error if the connection
cannot be established.

## Quest API

- `POST /api/quests` accepts `place` (`garden`, `market`, `neighborhood`, or
  `other`), `duration` (10–60 minutes), `energy` (`low`, `medium`, or `high`),
  `social` (`solo`, `gentle`, or `open`), and an optional list of quest titles
  to exclude.
- Every request is generated by the configured local Ollama model using the
  submitted place, duration, energy, social comfort, and excluded quest titles.
  An optional `pack` can be `mixed`, `noticing`, `connection`, `playfulness`,
  or `movement`.
  Thinking is disabled and output is capped to keep generation responsive; the
  model is kept loaded for ten minutes between requests. Generated results are
  validated for format, safety, excluded titles, social comfort, and total time.
- If Ollama is unavailable or returns invalid quests, the API returns HTTP 503
  with an actionable error. The PWA uses its bundled curated pack in that case.
- Progress is stored only in the browser's local storage; no account or
  progress API is used.

## Health checks

- `GET /` confirms that the API is responding.
- `GET /api/health` reports API and MongoDB connection status.
